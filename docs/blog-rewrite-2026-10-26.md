## 반영 결과

- 104편 모두 저장한 본문과 수정안이 일치한다. 새 글 생성이나 기존 글 삭제는 하지 않았다.
- 최초 작성일, ID, 제목, 주소, 카테고리, 태그, 댓글을 보존했다. 본문 수정에 따라 수정일은 갱신됐다.
- 기존 이미지 54개의 전체 등장 횟수 55회를 유지했다. 원본 이미지 파일도 URL별로 백업하고 해시를 확인했다.
- 각 수정 요청 직전·직후의 조회수가 같았다. 작업 시작 이후 증가한 조회수는 되돌리지 않았다. 검증에는 관리자 조회와 목록을 사용했다.

## 문체와 출처 보완

전체 소제목과 본문을 다시 읽고 70편의 대조 표현과 모호한 문장을 추가로 고쳤다. “A했는데 B했다”, “A하는 만큼 B한다”처럼 두 내용을 짝맞추는 표현을 줄이고 실제 문제·행동·조건을 설명했다.

| 기존 표현 | 수정 예 |
| --- | --- |
| 코드는 늘었는데 내가 따라가지 못했다 | AI가 만든 코드를 수정할 때 생긴 문제 |
| 남겨두는 만큼 정할 것도 있다 | 삭제된 사용자 복원과 같은 전화번호의 재가입 |
| 연결 이후에도 결정할 것이 있다 | 참가자 상태와 음소거 처리 |
| 핑은 되는데 아무것도 안 된다 | SSH와 관리 화면 접속 실패 |

출처의 발행일·버전·개정 이력을 최초 작성일과 대조했다. 최신판으로 바뀌는 링크는 가능한 한 당시 공식 버전 문서나 고정 커밋으로 교체했다. 대표적인 조치는 다음과 같다.

- 2022년 React 실습에서 2025년 CRA 지원 중단 설명과 현재 Vite 실습을 제외하고, CRA와 App.js를 사용한 당시 흐름을 유지했다. React 출처도 React 18 자료로 맞췄다.
- 2023년 JWT·OAuth 글의 RFC 9700(2025) 인용은 RFC 6749(2012), RFC 6819(2013), PKCE RFC 7636(2015) 등 당시 명세로 교체했다. 2026년 RTR 글에서는 작성일보다 이른 RFC 9700을 유지했다.
- NestJS·Jest·TypeORM·Spring·Kotlin 등의 근거를 작성일 이전 릴리스·문서 커밋으로 고정했다. 원래 설치 버전이 확인되지 않는 경우 그 버전을 실제로 사용했다고 주장하지 않았다.
- MySQL 8.4 문서의 처리도 글마다 구분했다. 2022년 글에는 이후 버전이므로 교체했고, 2024년 5월 글에서는 버전 출시일이 앞서지만 문서가 계속 갱신되므로 고정 자료를 사용했다.
- 본문에 ‘재작성 시 추가’나 ‘재작성 시 참고’ 같은 작업 안내를 남기지 않았다. 검토 이력은 별도 기록에 보관했다.

이번 문체 추가 수정에서는 코드 블록과 출처·이미지 URL을 그대로 유지했다. 작성 시점과 대조 표현에 관한 기준은 글쓰기 원칙에 추가했으며 기존 AGENTS.md의 필수 참고 지침을 통해 다음 작업에도 적용된다.

## 검증과 백업

전체 MCP 저장 결과와 목록을 다시 읽어 본문·메타데이터·댓글·이미지 보존을 확인했다. 코드 울타리와 본문의 재작성 안내 부재도 검사했다. 초기 39편의 JS/TS/JSX 코드 조각 45개와 중간 32편의 JS/TS 코드 조각 60개는 구문 검사를 통과했다. Promise 예제와 Haversine 경계 조건, 제곱수 판별의 전체 입력 범위, 폰켓몬의 완전 탐색 비교, 피보나치 C++의 입력 0~40을 확인했다. Kotlin 예제는 Kotlin 1.9.25/JDK 21에서 컴파일·실행했다. 전체 Nest/Spring/DB 애플리케이션 실행이나 모든 브라우저 화면 검증을 수행한 것은 아니다.

블로그 첫 화면과 서버 상태 확인 경로는 HTTP 200으로 응답했다. 이 작업은 글과 문서 수정이므로 애플리케이션 빌드·배포 코드는 변경하지 않았다. 문서 경로와 해당 변경의 `git diff --check`를 확인했다.
